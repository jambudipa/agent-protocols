# @jambudipa/a2a

[A2A v1.0](https://a2a-protocol.org) (Agent2Agent) for Effect v4: a server
and a client over all three protocol bindings (JSON-RPC 2.0, gRPC and
HTTP+JSON), at feature parity with
[`@a2a-js/sdk`](https://github.com/a2aproject/a2a-js) 1.3.0.

- The data model is a set of Effect Schemas in ProtoJSON form, generated by
  hand from the vendored `spec/proto/v1/a2a.proto`.
- The server is a request handler service with an agent executor contract,
  task and push notification stores, a push sender, and the bindings as
  `HttpRouter` layers and a gRPC server layer.
- The client picks a transport from the Agent Card, with interceptors,
  authentication with retry and Agent Card signatures.
- Interop tests run the reference SDK against this package in both
  directions.

## Install

```sh
npm install @jambudipa/a2a effect@~4.0.6 @effect/platform-node@~4.0.6
```

`effect` and `@effect/platform-node` are peer dependencies. The other peers
are optional, and only the entry points that need them load them:

| Peer                                                                | Needed by                                                                   |
| ------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `@grpc/grpc-js`, `@bufbuild/protobuf`                               | `./server/grpc`, `./client/grpc`, `./errors/grpc` and the v0.3 gRPC entries |
| `@effect/sql-pg`, `@effect/sql-mysql2` or `@effect/sql-sqlite-node` | `./server/sql` (through your `SqlClient`) and the `a2a-db` CLI              |

`jose` is a dependency; the card signing functions load it on first use.

## Serve an agent

An agent is an `AgentExecutor`. `execute` publishes events to the bus: a
message, or a task followed by status and artifact updates. The request
handler stores each event, streams it and sends it to push webhooks.

```ts
import { NodeRuntime } from '@effect/platform-node';
import { DateTime, Effect, Layer } from 'effect';
import type { AgentCard } from '@jambudipa/a2a';
import {
  AgentEvent,
  AgentExecutor,
  InMemoryTaskStore,
} from '@jambudipa/a2a/server';
import * as A2ANode from '@jambudipa/a2a/node';

const agentCard: AgentCard = {
  name: 'Echo Agent',
  description: 'Echoes the message back.',
  version: '1.0.0',
  supportedInterfaces: [
    {
      url: 'http://localhost:41241/',
      protocolBinding: 'JSONRPC',
      protocolVersion: '1.0',
    },
    {
      url: 'http://localhost:41241/',
      protocolBinding: 'HTTP+JSON',
      protocolVersion: '1.0',
    },
  ],
  capabilities: { streaming: true, pushNotifications: true },
  defaultInputModes: ['text/plain'],
  defaultOutputModes: ['text/plain'],
  skills: [
    { id: 'echo', name: 'Echo', description: 'Echoes.', tags: ['echo'] },
  ],
};

const EchoExecutor = Layer.succeed(
  AgentExecutor,
  AgentExecutor.of({
    execute: (context, bus) =>
      Effect.gen(function* () {
        const timestamp = DateTime.formatIso(yield* DateTime.now);
        yield* bus.publish(
          AgentEvent.statusUpdate({
            taskId: context.taskId,
            contextId: context.contextId,
            status: {
              state: 'TASK_STATE_COMPLETED',
              timestamp,
              message: {
                messageId: `${context.taskId}-reply`,
                role: 'ROLE_AGENT',
                parts: context.userMessage.parts,
              },
            },
          })
        );
      }),
    cancelTask: () => Effect.void,
  })
);

A2ANode.layerAgent({ agentCard, port: 41241 }).pipe(
  Layer.provide([InMemoryTaskStore.layer, EchoExecutor]),
  Layer.launch,
  NodeRuntime.runMain
);
```

`layerAgent` serves the Agent Card at `/.well-known/agent-card.json`,
JSON-RPC at `POST /` and HTTP+JSON at `/message:send`, `/tasks/{id}`, ...,
each also under `/{tenant}`. To mount the bindings elsewhere, or on another
platform, provide `A2AHttpRoutes.layer({ jsonRpcPath, restPrefix })` (or
`JsonRpcRoute`, `RestRoutes`, `AgentCardRoute` one by one) to
`HttpRouter.serve`, with `DefaultRequestHandler.layer({ agentCard })`.

### Request handler behaviour

The default handler follows the reference `DefaultRequestHandler`:

- `SendMessage` blocks until the task reaches a terminal or interrupted
  state, unless the request sets `returnImmediately`. A blocking call returns
  at `AUTH_REQUIRED` and keeps processing in the background.
- An executor that fails before its first event yields a task in
  `TASK_STATE_FAILED`; one that fails later yields a FAILED status update.
- `CancelTask` calls the executor's `cancelTask` and then interrupts the
  execution fiber; a task without a running execution is canceled directly.
- A request without `A2A-Version` asks for protocol 0.3; it is rejected
  (`-32009`, HTTP 400, gRPC `FAILED_PRECONDITION`) unless the card declares a
  0.3 interface and legacy compatibility is on.
- Tasks and push configs are scoped by tenant, then by owner. The owner is the
  user name of the caller, or `unknown`; provide `CurrentOwnerResolver` to
  change it, and a `userBuilder` to the routes to authenticate callers.
- Push notifications need `capabilities.pushNotifications`. The handler uses
  the provided `PushNotificationStore` and `PushNotificationSender`, else an
  in-memory store and `DefaultPushNotificationSender` on the provided
  `HttpClient` (5 second timeout, `Authorization: <scheme> <credentials>` or
  `X-A2A-Notification-Token`, in event order for each task, no retry).

### gRPC

```ts
import { A2AGrpcServer } from '@jambudipa/a2a/server/grpc';

const Grpc = A2AGrpcServer.layer({ port: 50051 }).pipe(
  Layer.provide(DefaultRequestHandler.layer({ agentCard })),
  Layer.provide([InMemoryTaskStore.layer, EchoExecutor, NodeCrypto.layer])
);
```

The service is `lf.a2a.v1.A2AService`. Errors carry the reference status
codes and a `grpc-status-details-bin` with a `google.rpc.ErrorInfo`. To use
your own grpc-js server, add `A2AService` with the implementation of
`grpcService()`.

### SQL stores

```ts
import { SqliteClient } from '@effect/sql-sqlite-node';
import {
  SqlPushNotificationStore,
  SqlTaskStore,
  migrateToLatest,
} from '@jambudipa/a2a/server/sql';

const Stores = Layer.mergeAll(
  SqlTaskStore.layer(),
  SqlPushNotificationStore.layer()
).pipe(Layer.provide(SqliteClient.layer({ filename: './a2a.db' })));
```

The tables are those of the reference SDK, so a database migrated by either
tool works with both. Migrate with `migrateToLatest()` at start-up or with
the CLI:

```sh
npx a2a-db upgrade --url sqlite:./a2a.db
npx a2a-db status --url postgres://localhost/a2a
npx a2a-db upgrade --sql --dialect mysql   # print the SQL, do not connect
```

## Call an agent

```ts
import { Effect, Stream } from 'effect';
import { FetchHttpClient } from 'effect/http';
import { ClientFactory } from '@jambudipa/a2a/client';

const program = Effect.gen(function* () {
  const factory = yield* ClientFactory.make();
  const client = yield* factory.createFromUrl('http://localhost:41241');
  const result = yield* client.sendMessage({
    message: {
      messageId: 'm-1',
      role: 'ROLE_USER',
      parts: [{ text: 'hello' }],
    },
  });
  yield* client
    .sendMessageStream({
      message: {
        messageId: 'm-2',
        role: 'ROLE_USER',
        parts: [{ text: 'stream' }],
      },
    })
    .pipe(Stream.runForEach((event) => Effect.log(event)));
  return result;
}).pipe(Effect.provide(FetchHttpClient.layer));
```

The factory tries `preferredTransports` first, then the interfaces of the
card in order; for each binding it prefers the interface with protocol
version 1.0. JSON-RPC and HTTP+JSON are on by default. For gRPC, add
`yield* GrpcTransportFactory.make()` from `@jambudipa/a2a/client/grpc` to
`transports` (it is scoped: the gRPC channels close with the scope).

Failures are typed: an A2A error of the server (`TaskNotFoundError`, ...) or
`A2ATransportError` for a failure outside the A2A error model.

- `ClientConfig` sets `polling` (send with `returnImmediately`),
  `acceptedOutputModes`, a default push config and `interceptors`.
- A `CallInterceptor` runs `before` each call (in order) and `after` it (in
  reverse); `before` may answer the call itself with `earlyReturn`.
- `withAuthentication(handler)` wraps an `HttpClient` so that requests carry
  the handler's headers and are retried once with the headers it asks for.

## Agent Card signatures

```ts
import {
  generateAgentCardSignature,
  verifyAgentCardSignature,
} from '@jambudipa/a2a';

const signed =
  yield *
  generateAgentCardSignature(privateKey, {
    alg: 'ES256',
    kid: 'key-1',
    typ: 'JOSE',
  })(agentCard);
yield *
  verifyAgentCardSignature((kid) => Effect.succeed(publicKeys[kid]))(signed);
```

Pass `signAgentCard` to `DefaultRequestHandler` to sign every card that the
server returns. The payload is the JCS (RFC 8785) form of the card without
`signatures` and without empty values, as the reference SDK computes it.

## A2A v0.3 compatibility

The `compat/v0_3` entries are adapters: they translate the v0.3 wire to the
v1.0 types and back, over the same request handler and client.

- Server, HTTP: pass `legacyCompat` of `@jambudipa/a2a/compat/v0_3/server`
  to the routes (`A2AHttpRoutes.layer({ legacyCompat })`). A request whose
  `A2A-Version` is absent or `0.3` then gets the v0.3 JSON-RPC methods
  (`message/send`, `tasks/get`, ...), the v0.3 REST routes under `/v1/...`
  and the v0.3 Agent Card. The card must declare interfaces with protocol
  version 0.3; `duplicateInterfacesForLegacy` (from
  `@jambudipa/a2a/compat/v0_3`) adds them.
- Server, gRPC: add `legacyGrpcService()` of
  `@jambudipa/a2a/compat/v0_3/server/grpc` to
  `A2AGrpcServer.layer({ additionalServices: [legacyGrpcService()] })` to
  serve `a2a.v1.A2AService` beside `lf.a2a.v1.A2AService`.
- Push notifications in the v0.3 body format need the sender of
  `createLegacyAwarePushNotificationSender()`; the default sender writes v1.0
  bodies.
- Client: `LegacyCompatClient.clientFactory()` of
  `@jambudipa/a2a/compat/v0_3/client` builds a factory that parses v0.3 cards
  and picks the v0.3 transport for a 0.3 interface. For gRPC, add
  `LegacyGrpcTransportFactory.make()` of
  `@jambudipa/a2a/compat/v0_3/client/grpc` to its transports.

## Differences from `@a2a-js/sdk` 1.3.0

- Promises, callbacks and Express are replaced by Effects, Streams and
  `HttpRouter` layers; stores, the executor and the push sender are
  `Context.Service`s.
- Both HTTP bindings accept `application/json` and `application/a2a+json`
  request bodies (the reference JSON-RPC route accepts only the first).
- A task id that contains a colon cannot be addressed over HTTP+JSON: the
  router matches `/tasks/{id}:cancel` with ids free of colons.
- The canonical form of a signed card keeps the content of its security
  schemes, as the specification and the Python SDK do. The reference SDK
  drops it, so a card with security schemes signed by one does not verify
  with the other.
- The client has no `ClientCallContext`; interceptors read call data from
  Effect services.
- With v0.3 compatibility on, a `/v1/...` REST request with a non-legacy
  `A2A-Version` gets 404 (the reference falls through to a tenant named
  `v1`), and the legacy JSON-RPC route reads requested extensions from
  `X-A2A-Extensions` only.

## Specification sources

`spec/` holds the specification at fixed revisions: the v1.0.1 proto and
`specification.md` from a2aproject/A2A `3303592`, the v0.3 proto and JSON
schema from `8d57eba`, and the googleapis protos from `cfc42c2`.
`npm run generate` regenerates `src/generated` from them with the local
`protoc-gen-es`, offline.
